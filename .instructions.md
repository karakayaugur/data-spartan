# Project Conventions

## Form Structure

All component forms must follow this signal-based pattern:

```typescript
form = {
  fieldName: signal(""),
  anotherField: signal(""),
};
```

Rules:

- Group all form fields under a single `form` object.
- Each field must be a `signal()` with an appropriate default value.
- Do NOT use standalone signals for form fields (e.g. `email = signal('')` is wrong).
- In templates, bind with `[(value)]="form.fieldName"`.
- Use `viewChildren(VALIDATABLE)` for collecting validatable inputs and call `.validate()` on each before submit.
- Do NOT add `errorMessage` signals or error UI to forms. API/HTTP errors are handled by a global error handler (interceptor). Forms only handle field-level validation via the `Validatable` interface.

Example:

```typescript
export class MyComponent {
  private validatables = viewChildren(VALIDATABLE);

  form = {
    email: signal(""),
    password: signal(""),
  };
  loading = signal(false);

  onSubmit() {
    const isValid = this.validatables().every((v) => v.validate());
    if (!isValid) return;

    this.loading.set(true);
    // call service with this.form.email(), this.form.password()
  }
}
```

Template binding:

```html
<form class="form" (submit)="onSubmit(); $event.preventDefault()" novalidate>
  <app-input-email [(value)]="form.email"></app-input-email>
  <app-input-password [(value)]="form.password"></app-input-password>
</form>
```

## Form Submit

- Always use `(submit)="onSubmit(); $event.preventDefault()"` with `novalidate` attribute.
- Do NOT use `(ngSubmit)` — it can cause page reloads in some scenarios.

## HTML Elements

- All HTML elements MUST use explicit closing tags. Do NOT use self-closing syntax (`/>`).
- Correct: `<svg lucideIcon="circle-alert" [size]="20"></svg>`
- Wrong: `<svg lucideIcon="circle-alert" [size]="20" />`

## Component File Structure

- Always separate HTML and CSS into their own files (templateUrl, styleUrl).
- Never use inline template or inline styles.
- Files: `component.ts`, `component.html`, `component.css`

## CSS Naming

- Do NOT use BEM naming (`--`, `__`).
- Use simple flat class names with descriptive prefixes.
- Correct: `.badge-success`, `.filter-search`, `.page-header`
- Wrong: `.badge--success`, `.filter__search`, `.page-header__title`

## HTTP Services

- All API services live in `core/http/<feature-name>/`.
- Each folder contains: `<name>.interface.ts`, `<name>.service.ts`, `index.ts`
- Interface and service are always separate files.
- Base URL pattern: `/proxyUrl/<endpoint>`
